# R8 功能开发文档

## 目录边界

- `ai-rules/`：只存放**绝对通用**的规则与模板；任何项目/功能相关内容**禁止**放入
- 功能开发文档统一存放：`dev-docs/features/<功能名>/`（工作区根，与 ai-rules 平级）
- git 保障：功能文档所在目录必须位于 git 仓库内（参照 R3「修改前置检查」）

## 自动流程（无需用户提醒）

每开发一个功能，自动执行：

1. **开始前**：创建 `dev-docs/features/<功能名>/`，写入需求文档（复用 `templates/task-prompt.md` 结构：任务/输入/处理/输出/边界/约束/验收）
2. **过程中**：每完成一个可验证步骤，更新文档（实现要点、验证结果）
3. **完成后**：自动执行三件事——
   - **审查**：对照验收清单逐项检查文档完整性
   - **总结**：输出功能总结（做了什么、关键决策、遗留问题）
   - **精简**：删除过程噪音，只保留结论与可复用信息

## 文档结构（单文件 `feature.md` 起步）

1. 需求（含验收清单）
2. 实现（改动文件、关键决策）
3. 验证（测试/编译结果）
4. 总结（结论、遗留项、经验）

## 补充约定

- 功能文档记录"决策与结果"，不写流水账
- 每功能完成后，若产生**通用**经验 → 提炼入 ai-rules（这是 ai-rules 唯一的补充入口）
- 用户未要求时也自动执行上述流程，不等用户提醒
