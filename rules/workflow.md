# R3 协作流程规则

## 修改前置检查（git 强制）

- 修改任何文件前，必须先确认该文件位于 git 仓库内
- 若所在目录无 git 仓库：**禁止修改**，必须先询问用户是否初始化（`git init`）
- 用户确认初始化后才允许写操作；未确认前不得改动任何文件
- 理由：无版本控制时，错误修改无法回滚、无从查找

## 编码任务五步

1. **复述确认**：先复述需求与验收标准，用户确认后才动手
2. **计划先行**：列出改动文件清单与实现步骤（含每步验证方式）
3. **小步实现**：任务拆成可独立验证的小块，逐块完成
4. **验证闭环**：每步运行测试/编译/静态分析，通过才继续
5. **最小改动**：只改与任务相关的文件，不顺手重构、不格式化无关代码

## 完成时自报（三行式）

- 改动了哪些文件，每处原因
- 哪些部分是假设/猜测
- 如何验证（编译 / 单测 / 逻辑推演）

## 变更请求处理

- 用户提出修改时，先确认影响范围再动手，避免连锁改动失控
