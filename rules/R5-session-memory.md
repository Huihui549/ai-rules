# R5 会话与记忆

## 新会话启动

- **每次新会话开始时**：读取 `ai-rules/README.md`，按索引加载规则（R1–R11）与当前角色档案（默认 `engineer`），再正式开始
- 会话中按交互意图**主动切换**角色，无需用户声明（判定见 `roles/README.md`）
- **同一会话内不再重复读取**：规则已加载，直接以编号引用
- 引用一律用编号，不粘贴全文

## 渐进式披露（其他文档按需读取）

- 新会话只读主文档（`ai-rules/README.md` 及索引所指规则/角色）；项目文档与历史文档**不自动读取**
- 对话涉及某份文档时，自行按需读取以恢复记忆
- **项目专属流程/标准文档**：不知其位置时先问用户要路径，不猜测、不假定项目文档结构
- 目的：省 context，同时保证需要时能快速恢复

## 肯定内容记录（自动执行，不等提醒）

- 用户对某次回答**明确肯定**（"对/是/没错/很好/可以"，且指向具体内容）→ 该回答即"已验证内容"，**下一次回答开始时**先记录再答新问题
- 记录位置：规则经验 → `rules/Rx-*.md`；功能经验 → `dev-docs/<项目名>/features/<功能名>/feature.md`；通用教训 → `logs/lessons.md`；会破坏单一职责则新建文档
- 格式：日期 + 被肯定的回答概要（1–2 句）+ 为何有效（1 句）
- 记录后仅报告改动文件，不执行任何 git 写操作（R4）

## 上下文压缩

- 规则（R1–R11）是对话的**持久准绳**，任何情况下必须完整；压缩可遗忘过程性内容，**禁止**丢失或模糊规则
- 压缩后规则缺失/模糊 → 主动重新读取 ai-rules（必要操作）；无法完整恢复 → 先向用户确认，不凭模糊记忆执行

## 成本控制（不牺牲完整性）

- 输出遵守 R1；文档更新用追加/增量，不整篇重写
- 一切"省钱"手段以规则完整为底线；冲突时保规则并明示成本
