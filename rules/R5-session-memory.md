# R5 会话与记忆

## 新会话启动

- **每次新会话（新对话窗口）开始时**，先读取 `ai-rules/README.md`（主文档索引），按其约定与规则索引加载规则（R1–R9 及后续）与当前角色档案，再正式开始
- 再读取 `roles/` 中**当前角色档案**（默认 `engineer`）；会话中根据交互意图**主动切换**角色（实现→engineer、学习→learner、评估→consultant、闲聊/灵感→friend），无需用户手动声明，判定标准见 `roles/README.md`
- **同一会话内每次提问不再重复读取**：规则已加载，直接以编号引用
- 规则引用一律用编号，不重复粘贴全文

## 渐进式披露（其他文档按需读取）

- 新会话只读主文档（`ai-rules/README.md` 及按索引加载的规则/角色）；项目文档库等历史/项目文档**不自动读取**
- 对话涉及某份文档的内容时，自行按需读取对应文件恢复记忆；读取后即可无缝衔接之前的工作
- **项目专属详细流程/标准文档**（如自动化开发手册）：AI 不知道其位置时，**先询问用户获取路径**，不猜测、不假定项目文档结构（彻底解耦）
- 目的：避免每次新对话消耗大量 context，同时保证需要时能快速恢复记忆

## 肯定内容记录（自动执行，不等提醒）

- 用户对某次回答**明确肯定**（"对/是/没错/很好/可以"，且指向具体内容）→ 该回答即"已验证内容"
- **下一次回答开始时**先完成记录，再回答新问题
- 记录原则：优先追加到已有相关文档（规则经验 → `rules/Rx-*.md`；功能经验 → `dev-docs/<项目名>/features/<功能名>/feature.md`；通用教训 → `logs/lessons.md`）；会破坏单一职责则新建文档
- git 保障：记录后确认文件已跟踪，新建文件即 `git add`，不积压
- 记录格式：日期 + 被肯定的回答概要（1–2 句）+ 为何有效（1 句）

## 上下文压缩

- 规则（R1–R7）是对话的**持久准绳**，任何情况下必须完整
- 压缩时可遗忘过程性内容（历史步骤、中间对话、已完成细节），**禁止**丢失或模糊规则
- 压缩后规则缺失/模糊 → 主动重新读取 ai-rules（必要操作，不属浪费）
- 无法完整恢复 → 先向用户确认，不得凭模糊记忆执行

## 成本控制（不牺牲完整性）

- 同一会话内不重复读取规则目录
- 引用规则用编号，不粘贴全文
- 输出遵守 R1 精炼原则
- 文档更新用追加/增量，不整篇重写
- 一切"省钱"手段以规则完整为底线；冲突时保规则并明示成本
