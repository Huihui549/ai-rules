# R5 会话与记忆

## 新会话启动

- **每次新会话开始时**：读取 `ai-rules/README.md` 按索引加载规则（R1–R11）与当前角色档案（默认 `engineer`）；项目侧读项目根 `AGENTS.md`（有则自动加载）
- **项目文档自检（自动，不等提醒）**：接触项目时检查 `dev-docs/<项目名>/` 与 `AGENTS.md` 是否齐备——缺则按 R6 骨架补齐并报告；每轮有重要更新也要检查并更新对应文件
- 会话中按交互意图**主动切换**角色（判定见 `roles/README.md`）
- **同一会话内不再重复读取**：规则已加载，直接以编号引用

## 渐进式披露（其他文档按需读取）

- 新会话只读主文档 + `AGENTS.md`；项目文档与历史文档**不自动读取**
- 对话涉及某份文档时按需读取以恢复记忆；项目专属流程文档位置不明时**先问用户要路径**，不猜测
- 目的：省 context，同时保证需要时能快速恢复

## 肯定内容记录（自动执行，不等提醒）

- 用户明确肯定某次回答（"对/是/没错/很好/可以"且指向具体内容）→ 该回答即"已验证内容"，**下一次回答开始时**先记录再答新问题
- 位置：规则经验 → `rules/Rx-*.md`；功能经验 → 功能级 `dev.md`；项目的坑 → 项目级 `pitfalls.md`；通用教训 → `logs/lessons.md`
- 格式：日期 + 概要（1–2 句）+ 为何有效（1 句）；记录后仅报告改动文件（不做 git 操作，R4）

## 会话收尾回填（自动，不等提醒）

- 触发：用户说"收尾/提交/今天到这"，或一轮任务完成且用户表示结束
- 动作：从本轮对话提炼并写入对应文件（归置见 R7）——
  - 本项目的坑 → 项目级 `pitfalls.md`
  - 决策（为什么选 A 不选 B）→ 项目级 `adr/`
  - 新出现的验收标准 → 功能级 `verify.md`
  - 功能做了什么 → 功能级 `dev.md`
  - 项目文档缺失 → 按 R6 骨架补齐
  - 仅当"跨项目适用且出现 ≥2 次"→ 才动 `rules/`
- 报告：只列回填了哪些文件 + 每条一句话，不复述原文
- 边界：只在已授权的项目工作范围内写文件；未授权时不写（R3）

## 上下文压缩

- 规则（R1–R11）是对话的**持久准绳**，任何情况下必须完整；压缩可丢过程性内容，**禁止**丢规则
- 压缩后规则缺失/模糊 → 主动重新读取；无法完整恢复 → 先向用户确认，不凭模糊记忆执行

## 成本控制（不牺牲完整性）

- 输出遵守 R1；文档更新用追加/增量，不整篇重写
- 一切"省钱"手段以规则完整为底线；冲突时保规则并明示成本
