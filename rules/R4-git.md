# R4 git 管理

## 修改前置检查（强制）

- 修改任何文件前，必须先确认该文件位于 git 仓库内（用只读命令实测，见下）
- 若所在目录无 git 仓库：**禁止修改**，先询问用户是否初始化（`git init`）；用户确认后才允许写操作
- 理由：无版本控制时，错误修改无法回滚、无从查找

## 跟踪范围

- 只跟踪**文本文件、给人看的文档**（如 `.md`）
- 不跟踪任何编译产物、二进制文件、缓存、依赖目录

## 忽略维护

- 新出现不需要跟踪的文件类型 → 更新 `.gitignore`
- `.gitignore` 本身**不跟踪**（配置类文件不属于"给人看的文件"）
- 已知忽略清单：编译产物（build/dist/`*.exe`）、缓存（`__pycache__`/`*.log`）、依赖目录（`node_modules`）

## 仓库边界确认

- 修改前确认工作区归属的 git 仓库边界，只在当前仓库范围内修改
- 所有改动必须能在 `git status` 中可见；不在当前仓库内的文件一律不碰
- 不擅自修改 SDK/父仓库下的文件，除非用户明确授权并知晓跨仓库影响

## 提交时机（AI 禁动 git；2026-08-27 定稿，2026-09-20 用户确认）

- **不执行任何 git 写操作**：不 `git add`（含暂存）/ `commit` / `reset` / `stash` / `checkout --` 等；文档、注释类改动不例外
- **只读检查白名单（唯一豁免）**：`git rev-parse` / `status` / `diff` / `log` / `branch --show-current` 允许直接执行（修改前置检查与 R1 的文件修改后审查需要）；白名单外一律不碰
- 改动一律留在工作区，由用户审查/暂存/提交；AI 只报告改动摘要
- 仅当用户本次对话**明确指令**具体 git 操作时才执行
- 旧例外已废止：`logs/lessons.md` 2026-09-18 行曾记"文档/注释可由 AI 主动提交"，自 2026-09-20 起废止
- 依据：`logs/lessons.md` 2026-09-18——判仓库须 `git rev-parse --show-toplevel` 实测，不得靠目录遍历深度推断
- 理由：git 交由用户完全掌控，AI 不碰

## 提交规范（供用户参考；AI 不代执行）

- Conventional Commits：`<type>: <简短中文描述>`，≤ 72 字符
- type：`feat` / `fix` / `docs` / `refactor` / `chore` / `sync`

## 已知代价

- `.gitignore` 不随仓库分发：克隆或迁移环境后需重建忽略规则
- 已接受：本目录为个人规范库，无协作者
