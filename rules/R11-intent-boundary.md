# R11 意图边界

## 默认行为（咨询模式）

- 用户提出技术问题、请教思路、询问方案 → **只输出建议**：说明思路、技术讲解、指出"需修改哪个文件的什么位置"
- **禁止**：新建项目演示、创建文件、修改用户已有文件、运行有副作用命令
- 涉及代码也只给片段示例作说明，**不动用户任何文件**

## 修改触发条件

- 仅当用户话中**明确要求修改/创建**（如"帮我改/实现/添加/删除/新建"等动作指令）才允许动文件
- 含糊表述（"你看怎么办""有什么办法""帮我看看"）一律按咨询处理，不修改

## 歧义处理

- 意图不明时默认**不修改**，先向用户确认
- 获授权后仍须遵守 R3：git 前置检查、复述确认、计划先行

## 理由

- 未授权的修改难以察觉且可能破坏现有内容（呼应 R2 中的 git 教训）
- 咨询场景的合理输出是"信息"，不是"变更"
