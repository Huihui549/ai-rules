# R8 工程代码卫生（防屎山）

> AI 辅助编程的最大风险不是错误代码，而是持续"无脑整合"——每次加一点、每次不清理、每次叠一层——三个月后谁都看不懂。

## 改动边界（呼应 R3 最小改动）

- 每次改动只做目标所**最低限度必要的**：不改无关代码/文件、不顺手重构、不统一命名风格（老代码不合规范也不得顺手"修正"，记 TODO 择日统一处理）、不扩展未明确的需求
- **判断标准**：这项改动不做、目标功能还能完成 → 不做
- **例外（必须同步处理）**：
  - 三个及以上位置有相同逻辑 → 必须提取为单一函数，即使只改了其中一处
  - 修改了 public 方法签名 → 必须同步更新所有调用方

## 代码删除（删代码比加代码更重要）

| 规则 | 禁止 |
|------|------|
| 删除，不注释保留 | `// oldMethod(); // 保留备用` |
| 废弃接口立即删除 | 方法/信号/属性不再被调用 → 删 |
| 不保留向后兼容 | 重构后新旧接口不得共存 |
| 无用成员立即删除 | 有写入无读取 → 删 |
| 重复代码必须提取 | 同样逻辑出现三次及以上 → 提取为函数 |

**铁律**：重构时删除行 ≥ 新增行；新增功能时代码量与复杂度成比例。

## 禁止 YAGNI

- 不预留参数、接口、分支、过度参数化；**现在没人用 → 不写**

## 禁止过度抽象

| 规则 | 说明 |
|------|------|
| 三次一样才提取 | 第 2 次仍是复制，第 3 次提取 |
| 禁止一行封装 | 不对单个库调用做包装函数 |
| 禁止为抽象而抽象 | 只有一个实现类的接口/基类不需要存在 |
| 不跨层链式调用 | 禁止 `a->b()->c()->d()` 式调用 |

## 禁止诡代码

| 禁止 | 示例 |
|------|------|
| 位运算传 bool 标志 | `setFlags(true\|false\|true)`（硬件寄存器操作除外） |
| 隐式类型转换 | `float x = 1 / 2;`（得 0） |
| 双重否定 | `if (!m_isNotReady)` |
| 无注释正则（>10 字符） | `/^([0-9A-F]{2}:){5}[0-9A-F]{2}$/` |
| `goto` | — |

## 屎山堆积模式（合并时发现即退回）

| 行为 | 正确做法 |
|------|----------|
| 复制类/函数只改 3 行 | 提取公共函数 |
| 在原函数中 `if (newCondition)` 追加 | 策略/状态模式 |
| 类持续添加属性（5→20） | 拆类 |
| `#include` 只增不删 | 定期清理 |
| 日志无开关散布 | 日志分级 + 编译开关控制 |

## 性能金律

- 不改没证明瓶颈的代码；改完必测，测必记录；优化中不顺手重构
- 收益 <10% 的微优化一般不值得，除非有充分理由

## CR 通用检查项（每次代码审查必查）

- 无"可能以后用到"的预留代码
- 新增类/函数/属性有明确调用方
- 无复制粘贴仅改几行的代码块
- 重构时删/增比健康
- 前后数据在同一平台/编译配置下测得（性能类）

## 规则优先级（P0–P3）

| 优先级 | 含义 |
|--------|------|
| P0 | 本规则"强制"项 — 违反即不允许合并 |
| P1 | 优先/推荐 — 无充分理由不得违反 |
| P2 | 平台/框架官方惯例 — P0/P1 未覆盖时默认遵循 |
| P3 | 经用户确认的临时/特殊约定 |
