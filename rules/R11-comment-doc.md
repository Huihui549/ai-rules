# R11 代码注释与文档分工

> 一句话：**代码里留路标，文档里写全文。**

## 分工（强制）

| 内容 | 写在哪 | 要求 |
|------|--------|------|
| 这段代码做什么、为什么这样做 | 代码注释 | 1 行说清；说不清 → 说明该写进文档 |
| 协议帧格式、状态机全貌、参数取值表、算法原理、联调用例、扩展步骤 | 功能文档（R6：`dev-docs/<项目名>/features/<功能名>/`） | 详尽、成表、可重放 |
| 代码里为什么不能用某个值/顺序（隐性约束） | 代码注释 | 1 行，必须写 |

- **禁止在代码里用大段注释解释原理**：超过 3 行的说明性注释一律移到文档，代码处只留一句摘要 + 文档指引（如 `/* 协议见 doc/蓝牙通讯功能文档.md */`）。
- **禁止无注释**：函数、状态机分支、协议字段、魔数、时序处理**必须**有注释；宁可一句，不可没有。
- 注释写"**为什么**"，不写"是什么"：`bt_timer = 0u;  /* 收到字节，重新计数 */`（好）；`bt_timer = 0u;  /* 把 bt_timer 赋值为 0 */`（废话，删除）。

## 注释粒度

| 位置 | 要求 |
|------|------|
| 文件头 | 一句话说明本文件职责 + 关联文档路径（如有） |
| 函数 | 1 行说明用途；有副作用/时序要求时补 1 行 |
| 分支/字段 | 只在含义不直观处标注（如 `clr=1 读后清零`） |
| 魔数 | 必须解释来源或含义（如 `20 次 × 5ms = 100ms`） |

## 与其它规则的关系

- 补充 R6：R6 管文档怎么写，本规则管**什么内容该去文档、什么该留代码**。
- 受 R3 保护：**注释无错不删**；重构时注释必须原样搬到新位置。
- 呼应 R1：注释同样适用精炼原则，一个意思只表达一次。

## 自检（编码任务完成前）

1. 新增/修改的每个函数、分支、魔数都有注释吗？
2. 有没有超过 3 行的说明性注释？→ 移入文档。
3. 注释是否在解释"是什么"而非"为什么"？→ 删或改写。
4. 文件头是否指向对应文档（有文档时）？

## 来源

- 2026-09-14 用户定稿：代码注释要简洁、越简洁越好，但绝不能没有；详细内容应写在文档中，这是文档的关键作用之一，不要在代码里写大量注释解释。
