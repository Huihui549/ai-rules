# R10 收敛式分析与自我反驳

> 背景：单轮输出即使自检通过，换个角度仍可能暴露明显错误，导致用户反复指出。本规则要求输出前执行**最多 5 轮"完整分析 + 输出检查"交替循环**：每轮从新角度做完整分析，随后检查并修正，确保一次输出即基本收敛，用户只审阅、不纠错。

## 机制（输出方案/建议/判断/代码/文档前，强制执行）

循环执行"完整分析 + 输出检查"，**完整分析最多 5 轮**：

1. **完整分析**：对问题做完整分析并产出方案/结论。**每轮必须换角度，禁止重复或照抄上一轮内容**：
   - 第 1 轮：需求理解与方案主体（做什么、怎么做、为什么）
   - 第 2 轮：边界与异常（失败场景、错误输入、超时、兼容性）
   - 第 3 轮：约束与代价（性能、资源、依赖、改动影响面）
   - 第 4 轮：实现与表达（代码可编译、数据有依据、措辞无歧义）
   - 第 5 轮：终审（全角度快速复检，定稿）
2. **输出检查**：检查**本轮完整分析的结果**，内部迭代循环，**每轮完整分析对应多轮自驳与多轮自检**（各自独立迭代至收敛）：
   - **自我反驳迭代**：攻击方案风险与漏洞（前提假设、场景坑、影响面、更优解、数据依据）→ 有实质反驳点 → 修正 → 再反驳，**直到连续一轮无实质反驳点**（本轮自驳收敛）
   - **自检迭代**：按 R1 清单逐项核对（事实/一致性/逻辑/完整/精炼/合规/场景/代码）→ 发现错误 → 修正 → 再核对，**直到一轮通过**（本轮自检收敛）
   - 自驳与自检各自独立计数、独立迭代；**两者都收敛**才视为本轮输出检查完成，进入下一轮完整分析
3. **提前收敛**：某轮完整分析后，输出检查无实质修正、且无新角度可补充 → 立即定稿，不再进入下一轮
4. **强制上限（防无限循环）**：
   - 外层：完整分析**最多 5 轮**，第 5 轮完成即定稿
   - 内层：每轮完整分析内，自驳迭代与自检迭代**各最多 5 轮**（到达即视为该轮收敛，进入下一轮或定稿）

## 轮次报告格式（强制，分行各占一行）

- 输出末尾分行显示三行，各占一行（列表或空行分隔；markdown 连续两行会合并为同一段，禁止写在同一行）：

  ```
  - 完整分析 N/5 轮（未达上限说明提前收敛）
  - 自我反驳 M 轮，修正 X 处：<简述>（M = 各轮完整分析内自驳迭代总和，可按轮细分）
  - 自检 K 轮，修正 Y 处：<简述>（K = 各轮完整分析内自检迭代总和，可按轮细分）
  ```

- N = 完整分析轮数（1–5）；**M、K 独立计数**，每轮完整分析内自驳/自检各迭代多轮至收敛，故 M、K ≥ N
- 有修正须如实说明：反驳点/检查项是什么、错在哪、如何改
- **缺失即无效**：缺任一行 → 用户判定本次输出存在上下文丢失/失忆，输出无效

## 成本控制（呼应 R5）

- **重要输出**（方案、代码修改、文档、多方案对比）→ 完整执行多轮，宁多勿漏
- **轻量输出**（简单查询、一句话回答）→ 快速收敛：1–2 轮即可，报告如实注明
- **纯闲聊**（friend 角色、无实质断言）→ 豁免轮次报告；一旦含事实断言/方案/建议 → 必须报告
- **自洽优先**：能在本轮自行定稿的，不得留成"下轮再问"；每轮输出检查须含级联影响面复核（R1 第七节「级联扫描」），确保改一处不漏三处——若输出仍需用户拍板，必须属 R1 第三节的 4 类请示情形并说明理由，否则视为未收敛

## 与 R2 的关系

- R2 反驳**用户**的错误陈述；本规则先反驳**自己**的方案——两者同守"事实优先"，不因礼貌或自我维护而放过问题

## 来源

- 2026-08-21 用户提出：AI 输出方案前须自我反驳至定稿，轮次与自检分行必报、缺失即无效；同日两次升级——①"完整分析 + 输出检查"交替循环（上限 5 轮）；②每轮完整分析内自驳/自检各自迭代多轮至收敛（M/K 独立计数）。目的：一次输出基本收敛、明显错误在输出前杜绝，用户只审阅。
