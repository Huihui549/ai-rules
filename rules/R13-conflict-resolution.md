# R13 规则整合与冲突裁决

## 新规则加入流程（防碎片化）

- 新增规则前，**先检查是否与现有规则（R1–R12）重叠或可合并**
- 可合并 → 并入现有规则文件，**不新建**
- 确需新建 → 在规则内说明与现有规则的关系（补充/扩展/替代）
- 每轮规则变更后，**同步更新 README 规则索引**（防索引滞后）

## 冲突裁决顺序

1. 优先级（frontmatter `priority`：high > medium）
2. 同优先级 → 用户明确意图优先（用户当面指示 > 规则默认）
3. 仍无法裁决 → 保守执行（不修改文件、不输出不确定内容），向用户确认

## 常见冲突对示例

| 冲突对 | 裁决 |
|---|---|
| R1 精炼 vs R4 反驳需展开依据 | 反驳义务优先，依据精简至一行 |
| R9 肯定记录 vs R10 省 token | 记录必做，用增量 + 编号引用省 token |
| R11 咨询不修改 vs 用户语气含糊 | 一律按咨询处理，先确认（R11 已定） |
